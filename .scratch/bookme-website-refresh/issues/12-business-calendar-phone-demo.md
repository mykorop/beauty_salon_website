# 12: Показати календар BookMe Business у телефоні та перевірити готовий сайт

**What to build:** Відвідувач бізнес-секції RO/EN бачить у телефоні справжню структуру календаря BookMe Business: перемикання періоду, пошук клієнта та картку запису. Вигляд і керування узгоджені з клієнтською демонстрацією; сценарій зрозумілий салонам і незалежним майстрам. Готовий сайт із вебпосиланням та обома телефонами проходить спільні перевірки швидкості, доступності й браузерної сумісності, закріплені в CI.

**Blocked by:** 09: Підтвердити швидкість і доступність повного сайту та закріпити їх у CI; 10: Відкрити вебдодаток із навігації та головної BookMe; 11: Показати анімований запис клієнта в реалістичному телефоні.

## Answer

Реалізовано телефон BookMe Business у бізнес-секції RO/EN: календар на сьогодні
→ тиждень → місяць → пошук Ana Demo → читання деталей картки → очищення пошуку.
Список змінюється за трьома фіксованими вигаданими записами. Спільний із клієнтським
телефоном запис: Manichiură / Manicure, Mara Luca, 15 жовтня 2026,
14:30 Europe/Chisinau, 1 h, 300 MDL, Confirmată / Confirmed. Підпис прямо пояснює
відсутність живої синхронізації.

Використано спільний PhoneDemo та незмінений незалежний контролер відтворення.
Корпус збільшено на 40 px, щоб нижня навігація не перекривала третю картку на
320 px; регресію спочатку відтворено тестом перекриття тексту. Стару ілюстрацію
AppPreview та її невикористаний контент видалено. Нових бібліотек, app runtime,
API-викликів, дозволів пристрою або реальних персональних даних немає.

[Спільний звіт і знімки обох телефонів](../../../design/calendar-demo/README.md)
містять порівняння з локальними застосунками на демонстраційних даних, RO/EN на
320/768/1440 px, дерева доступності, команди, вимірювання й незавершені ручні
перевірки. Локальний мобільний репозиторій не змінено.

Фінальні перевірки на єдиній production-збірці:

- `npm run check`: 0 errors / warnings / hints; `npm run build`: 8 сторінок + 404.
- `npm test`: **1 046 passed, 142 intentional skips**, 0 failures / flaky / retries.
  Збережено Chromium, Firefox, WebKit, reduced motion і no-JS, обидві демонстрації,
  усі вебпосилання та FormBold із підміненими відповідями.
- Кожна головна: **1 409 B JS / 6 608 B CSS gzip**. Юридичні сторінки:
  **0 B JS / 2 179 B CSS**. Ліміти 20 000 / 40 000 B не змінено.
- `npm run test:lighthouse`: **48/48** пройшли; Performance medians **98–100**,
  Accessibility / Best Practices / SEO **100 у кожному запуску**. Найбільші
  медіани: LCP **1 654 ms**, CLS **0,07935**, TBT **0 ms**.
- `npm run package:site`: статичний архів із 39 файлами; підтверджено точний
  побайтовий збіг із `dist/`, дев'ять HTML-документів і відсутність зайвих файлів.
  SHA-256 та посилання на артефакт — у звіті. Деплою та змін DNS/CDN немає.

**Задачу залишено `needs-info`:** потрібні людські перевірки VoiceOver,
клавіатурного обходу/фокуса, справжнього 400% browser zoom та OS reduced motion.
Знімки й автоматизовані перевірки не видані за ці ручні результати. Задача 09
також має незакриті ручні перевірки та підтвердження фінального контенту; після
зміни цього контенту спільні gates потрібно повторити. Локальний успішний запуск
не видано за виконаний remote CI або перевірку опублікованого сайту.
