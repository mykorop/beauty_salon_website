# 09: Підтвердити швидкість і доступність повного сайту та закріпити їх у CI

**What to build:** Повністю зібраний сайт проходить погоджені критерії швидкості, SEO та доступності на всіх сторінках. Команда отримує відтворювані перевірки й звіти, які виявляють майбутні регресії.

**Blocked by:** 03: Показати клієнтам і бізнесу можливості BookMe та правильні завантаження; 04: Дати відповіді на запитання та доступний канал підтримки; 05: Пояснити конфіденційність і видалення акаунта відповідно до аудиту; 06: Опублікувати зрозумілі умови для клієнтів, салонів і майстрів; 07: Створити впізнавані favicon і прев’ю посилань BookMe; 08: Забезпечити коректну індексацію всіх мовних сторінок.

**Status:** needs-info

- [ ] Перевіряється готова production-збірка всіх восьми сторінок із фінальним контентом. Це завершальна інтеграційна перевірка, а не заміна тестів попередніх задач.
- [x] Оптимізовані розміри/формати/пріоритети зображень, font loading, CSS і JavaScript; немає зміщень через незарезервовані розміри ресурсів або контенту, прихованого до виконання скрипту.
- [x] На кожній сторінці власний JavaScript не перевищує 20 КБ gzip, CSS — 40 КБ gzip; бюджет і спосіб його обчислення перевіряються автоматично.
- [x] Lighthouse CI запускається тричі для кожної сторінки у mobile та desktop профілях із зафіксованими версіями інструментів. Медіана Performance не нижча 95; Accessibility, Best Practices і SEO дорівнюють 100 у кожному запуску.
- [x] Медіани лабораторних метрик для кожної сторінки й профілю: LCP ≤2,5 с, CLS ≤0,1, TBT ≤200 мс. Невиконані критерії виправляються, а не приховуються вимкненням аудитів.
- [x] Playwright проходить у Chromium, Firefox та WebKit; перевірені мобільна навігація, мовні переходи, старі URL, FAQ, форми з підміненими відповідями, юридичні посилання, 404 і сценарії без JavaScript.
- [ ] Axe не знаходить порушень у перевірених сторінках та станах меню/форми. Вручну перевірені клавіатура, VoiceOver, видимий і не перекритий фокус, контраст, 400% zoom, reflow 320 CSS px і reduced motion.
- [x] Інтерактивні цілі спроєктовані щонайменше 44×44 CSS px; помилки й успіх форми зрозумілі скринрідеру, розкладка не має горизонтального прокручування на вузьких екранах.
- [x] CI запускає типи, збірку, функціональні тести, axe та Lighthouse й зберігає звіти/знімки помилок. Робочі повідомлення FormBold, production-акаунти та персональні дані не використовуються.
- [x] Підсумковий звіт містить фактичні результати та окремо пояснює ручну WCAG-перевірку і майбутні польові CWV: LCP ≤2,5 с, INP ≤200 мс, CLS ≤0,1 на 75-му перцентилі. Лабораторний TBT не названо вимірюванням польового INP.
- [x] Передано статичний артефакт та інструкцію розгортання/перевірки HTTPS, кешування, HTTP-статусів і публічного PageSpeed. Автоматична публікація, зміни DNS/CDN і підключення Search Console не виконуються.

## Answer

Реалізовано автоматичні production quality gates для всіх восьми сторінок. CI
перевіряє типи, статичну збірку, Chromium/Firefox/WebKit з JavaScript та мобільні
сценарії без нього, axe, gzip-бюджети й 48 запусків Lighthouse. Звіти, traces і
знімки помилок зберігаються як артефакти; статичний архів передається після
успішних перевірок. Публікації, змін DNS/CDN і підключення Search Console немає.

Збільшено недостатні інтерактивні цілі (мовні, юридичні й support-посилання)
до мінімуму 44×44 px. Додано перевірки reflow 320 px, видимого фокуса та його
перекриття, reduced motion і форм при 320 px. Усі browser-запити за межі локального
сайту блокуються, відповіді FormBold підмінені. macOS WebKit використовує рідний
Option-Tab; очікування шрифтів перевіряє `document.fonts.status`, щоб Firefox
без JavaScript не зависав на automation promise `fonts.ready`.

[Повний звіт з фактичними вимірюваннями](../../../docs/quality-report.md):

- `npm run check`: 0 errors / warnings / hints; production-збірка: 8 сторінок + 404.
- Повний `npm test`: **734 passed, 76 intentional skips, 0 failed, 0 flaky**.
  Axe: 0 порушень у всіх виконаних скануваннях. Пропуски пояснені у звіті.
- Lighthouse: **48/48** запусків успішні; mobile Performance median **97–100**,
  desktop **100**. Accessibility / Best Practices / SEO — **100 у кожному запуску**.
  Найбільші медіани: LCP **1654 мс**, CLS **0.08759**, TBT **0 мс**.
- JavaScript: **534 bytes gzip** на кожній головній, **0** на юридичних сторінках.
  CSS: **4405 / 2145 bytes gzip** відповідно. Обидва бюджети перевірені також
  навмисно завеликими JS/CSS-ресурсами: перевірки впали на правильному ліміті,
  оригінальну збірку відновлено перед фінальним suite.
- Створено `artifacts/bookme-website.tar.gz`, SHA-256 записаний у звіті.
  Є [інструкція передачі та перевірки розгортання](../../../docs/deployment.md)
  і [відтворювані команди та ручна процедура](../../../docs/quality-gates.md).

**Задачу не закрито:** ticket 05 залишається `needs-info` щодо підтверджених
правових підстав; після зміни остаточного контенту gates треба повторити.
Ручні VoiceOver, 400% browser zoom, візуальна перевірка контрасту, клавіатурний
обхід і OS reduced motion ще не підтверджені людиною. Автоматичні axe, 320 px
і focus-перевірки не видані за ручний WCAG-аудит. Майбутні польові CWV описані
окремо: p75 LCP ≤2.5 s, INP ≤200 ms, CLS ≤0.1; лабораторний TBT не є польовим INP.
Локальні результати не видані за виконаний remote CI або production PageSpeed.
